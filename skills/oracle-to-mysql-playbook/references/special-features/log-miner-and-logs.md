# Oracle Log Miner and MySQL Logs

> Source: AWS Oracle→Aurora MySQL Migration Playbook
> URL: https://docs.aws.amazon.com/dms/latest/oracle-to-aurora-mysql-migration-playbook/chap-oracle-aurora-mysql.special.log.html

**Conversion category:** Manual (three-star feature compatibility) — MySQL has no LogMiner; a workaround exists (mysqlbinlog).
**SCT automation:** N/A

## Oracle

Oracle Log Miner queries online and archived redo logs through a SQL interface, allowing historical analysis of past DML.

```sql
-- find current redo log
SELECT V$LOG.STATUS, MEMBER
FROM V$LOG, V$LOGFILE
WHERE V$LOG.GROUP# = V$LOGFILE.GROUP#
AND V$LOG.STATUS = 'CURRENT';

-- add the log file and start Log Miner
BEGIN DBMS_LOGMNR.ADD_LOGFILE('/u01/app/oracle/oradata/orcl/redo02.log'); END;
/
BEGIN DBMS_LOGMNR.START_LOGMNR(options=>dbms_logmnr.dict_from_online_catalog); END;
/

-- query captured DML
SELECT TO_CHAR(TIMESTAMP,'mm/dd/yy hh24:mi:ss') TIMESTAMP,
       SEG_NAME, OPERATION, SQL_REDO, SQL_UNDO
FROM V$LOGMNR_CONTENTS
WHERE TABLE_NAME = 'EMPLOYEES' AND OPERATION = 'UPDATE';
-- SQL_REDO / SQL_UNDO give the redo and compensating statements
```

## MySQL

The **mysqlbinlog** utility is the Aurora MySQL equivalent of Log Miner, reading the server's binary log (analogous to redo logs). Aurora MySQL exposes four logs:

- **Error log** — errors plus start/stop events (generated by default; written to `mysql-error.log`, flushed every 5 min into `mysql-error-running.log`, rotated hourly, 24h retained).
- **General query log** — connect/disconnect/queries.
- **Slow query log** — slow statements.
- **Bin log** — row- and statement-level command records (used for replication).

Logs are viewable via the RDS console/API/CLI/SDKs, or by directing them to a database table and querying it. Amazon RDS rotates all log files.

Download/read the binary log:

```sql
SHOW BINARY LOGS;   -- errors if binlog not activated; else lists binlog files
```

```bash
mysqlbinlog \
  --read-from-remote-server \
  --host=mysql-cluster1.cluster-xxxx.us-east-1.rds.amazonaws.com \
  --port=3306 \
  --user naya --password mysql-bin-changelog.0098
```

Logging-control parameters (database parameter group):
- `slow_query_log` (0/1), `general_log` (0/1)
- `long_query_time` (seconds; default 10; min 0; microsecond resolution only with `log_output=FILE`)
- `log_queries_not_using_indexes` (0/1)
- `log_output` — `TABLE` (writes to `mysql.general_log` / `mysql.slow_log`, default), `FILE` (filesystem, rotated hourly), or `NONE`.

Check current logging:

```sql
select @@GLOBAL.log_output, @@GLOBAL.slow_query_log, @@GLOBAL.general_log;
```

Binlogs are purged ASAP by RDS but must remain available for mysqlbinlog — set a retention period:

```sql
call mysql.rds_set_configuration('binlog retention hours', 24);
```

Logs can also be published to Amazon CloudWatch Logs for real-time analysis, alarms, metrics, and durable storage.

## Conversion notes

- Replace Log Miner DML reconstruction (`SQL_REDO`/`SQL_UNDO` from `V$LOGMNR_CONTENTS`) with **mysqlbinlog** reading the binary log.
- Ensure the binary log is enabled and set `binlog retention hours` long enough to download logs before RDS purges them; monitor storage usage.
- Use `log_output=TABLE` to query general/slow logs as tables (closest to Oracle's SQL-interface querying); use CloudWatch Logs for monitoring/alerting.
- The binlog format is event/statement based, not a SQL `V$` view — analysis tooling differs.
