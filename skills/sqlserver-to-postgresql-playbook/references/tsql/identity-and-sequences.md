## SQL Server

Automatic enumeration for surrogate keys via: `IDENTITY` column property, `SEQUENCE` objects, and functions `IDENTITY`/`NEWSEQUENTIALID`.

**IDENTITY property** — one numeric column per table; explicit seed/increment. Does not enforce uniqueness (add PK/UK separately). Retrieve generated values with `@@IDENTITY`, `SCOPE_IDENTITY`, `IDENT_CURRENT`. Manage with `DBCC CHECKIDENT` (reseed).

```sql
IDENTITY [(<Seed Value>, <Increment Value>)]

CREATE TABLE MyTABLE
( Col1 INT NOT NULL PRIMARY KEY NONCLUSTERED IDENTITY(1,1),
  Col2 VARCHAR(20) NOT NULL );

DECLARE @LastIdent INT;
INSERT INTO MyTable(Col2) VALUES('SomeString');
SET @LastIdent = SCOPE_IDENTITY()
```

**SEQUENCE** — table/column-independent object; retrieve via `NEXT VALUE FOR`. Advantages over IDENTITY: get value before INSERT, share across tables/columns, easier restart/modification, ranges via `sp_sequence_get_range`.

```sql
CREATE SEQUENCE <Sequence Name> [AS <Integer Data Type> ]
START WITH <Seed Value>
INCREMENT BY <Increment Value>;

ALTER SEQUENCE <Sequence Name>
RESTART [WITH <Reseed Value>] INCREMENT BY <New Increment Value>;

CREATE SEQUENCE MySequence AS INT START WITH 1 INCREMENT BY 1;
CREATE TABLE MyTable
( Col1 INT NOT NULL PRIMARY KEY NONCLUSTERED DEFAULT (NEXT VALUE FOR MySequence),
  Col2 VARCHAR(20) NULL );
```

**IDENTITY function** (only in `SELECT … INTO`) and **NEWSEQUENTIALID** (sequential GUID for `UNIQUEIDENTIFIER` DEFAULT):

```sql
SELECT IDENTITY(INT, 100, 1) AS SurrogateKey, Col1, Col2, Col3
INTO MyNewTable FROM MySourceTable ORDER BY Col1 DESC;

CREATE TABLE MyTable
( Col1 UNIQUEIDENTIFIER NOT NULL PRIMARY KEY NONCLUSTERED DEFAULT NEWSEQUENTIALID() );
```

## PostgreSQL

`CREATE SEQUENCE` is mostly compatible with SQL Server. Parameters: `TEMPORARY`/`TEMP`, `IF NOT EXISTS`, `INCREMENT BY` (default 1), `START WITH`, `MAXVALUE`/`NO MAXVALUE`, `MINVALUE`/`NO MINVALUE`, `CYCLE`/`NO CYCLE` (default NO CYCLE), `CACHE` (no `NOCACHE`; default no pre-cache, min 1), `OWNED BY`, `AS data_type` (PG10+: smallint/integer/bigint, default bigint).

```sql
CREATE [ TEMPORARY | TEMP ] SEQUENCE [ IF NOT EXISTS ] name
[ INCREMENT [ BY ] increment ]
[ MINVALUE minvalue | NO MINVALUE ] [ MAXVALUE maxvalue | NO MAXVALUE ]
[ START [ WITH ] start ] [ CACHE cache ] [ [ NO ] CYCLE ]
[ OWNED BY { table_name.column_name | NONE } ]
```

Examples:

```sql
CREATE SEQUENCE SEQ_1 START WITH 100 INCREMENT BY 1 MAXVALUE 99999999999 CACHE 20 NO CYCLE;
DROP SEQUENCE SEQ_1;
SELECT * FROM INFORMATION_SCHEMA.SEQUENCES;   -- or \ds

CREATE TABLE SEQ_TST
(COL1 NUMERIC DEFAULT NEXTVAL('SEQ_1') PRIMARY KEY, COL2 VARCHAR(30));
INSERT INTO SEQ_TST (COL2) VALUES('A');

CREATE SEQUENCE SEQ_1 START WITH 100 INCREMENT BY 1 OWNED BY SEQ_TST.COL1;
SELECT CURRVAL('SEQ_1');
SELECT NEXTVAL('SEQ_1');
SELECT SETVAL('SEQ_1', 200);
ALTER SEQUENCE SEQ_1 MAXVALUE 1000000;
```

**IDENTITY columns** (PG10+, SQL-standard, closer to SQL Server than SERIAL):

```sql
CREATE TABLE emps (
  emp_id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  emp_name VARCHAR(35) NOT NULL);

INSERT INTO emps (emp_name) VALUES ('Robert');
INSERT INTO emps (emp_id, emp_name) VALUES (DEFAULT, 'Brian');
```
For `SERIAL` and `GENERATED BY DEFAULT` columns you can insert explicit values (must not violate PK); `GENERATED ALWAYS` requires `OVERRIDING SYSTEM VALUE` (verified).

**SERIAL pseudo-type** (auto-creates a sequence, adds NOT NULL; also `SMALLSERIAL`, `BIGSERIAL`):

```sql
CREATE TABLE SERIAL_SEQ_TST(COL1 SERIAL PRIMARY KEY, COL2 VARCHAR(10));
-- auto sequence named TABLENAME_COLUMNNAME_seq, e.g. serial_seq_tst_col1_seq

ALTER SEQUENCE serial_seq_tst_col1_seq RESTART WITH 100 INCREMENT BY 10;

-- compound PK with SERIAL:
CREATE TABLE SERIAL_SEQ_TST (COL1 SERIAL, COL2 VARCHAR(10), PRIMARY key (COL1,COL2));
```

## Summary

| Feature | SQL Server | Aurora PostgreSQL |
|---|---|---|
| Independent SEQUENCE object | `CREATE SEQUENCE` | `CREATE SEQUENCE` |
| Auto-enumerator column property | `IDENTITY` | `GENERATED { ALWAYS \| BY DEFAULT } AS IDENTITY` (avoid `SERIAL` in new DDL) |
| Reseed sequence | `DBCC CHECKIDENT` | `ALTER TABLE t ALTER COLUMN c RESTART WITH n`, or `SETVAL(pg_get_serial_sequence('t','c'), n)` |
| Column restrictions | Numeric | Numeric |
| Control seed/interval | `CREATE/ALTER SEQUENCE` | `CREATE/ALTER SEQUENCE` |
| Sequence value across restarts | Maintained (identity cache can jump after a crash) | Maintained (cached values are lost after a crash/failover, leaving gaps) |
| Explicit values to column | Not allowed by default; needs `SET IDENTITY_INSERT ON` | `GENERATED ALWAYS`: rejected unless `INSERT … OVERRIDING SYSTEM VALUE`; `BY DEFAULT`/`SERIAL`: allowed |
| Sequential GUID | `NEWSEQUENTIALID()` | `uuidv7()` (PG 18) |
| Random GUID | `NEWID()` | `gen_random_uuid()` (core since PG 13) |

## Conversion notes
- `IDENTITY` property → identity column, never `SERIAL` in new DDL. `GENERATED ALWAYS AS IDENTITY` matches SQL Server's default of rejecting explicit values (verified on 18.6: error 428C9, hint `OVERRIDING SYSTEM VALUE`); `GENERATED BY DEFAULT` is easier for data loads and AWS DMS. Pick one convention per migration and record it.
- `SET IDENTITY_INSERT t ON; INSERT …; SET IDENTITY_INSERT t OFF` → `INSERT INTO t (id, …) OVERRIDING SYSTEM VALUE VALUES (…)` for `ALWAYS` columns, or a plain insert for `BY DEFAULT`.
- `IDENTITY(1,1)` seed/increment → `GENERATED … AS IDENTITY (START WITH 1 INCREMENT BY 1)`. Identity columns are implicitly `NOT NULL`; like SQL Server, they do not imply uniqueness, so keep the PK/UK.
- Standalone `SEQUENCE` → `CREATE SEQUENCE`; `NEXT VALUE FOR` → `NEXTVAL('seq')`; current value → `CURRVAL`/`SETVAL`.
- Reseeding: `DBCC CHECKIDENT('t', RESEED, n)` → `ALTER TABLE t ALTER COLUMN id RESTART WITH n+1`, or `SETVAL(pg_get_serial_sequence('t','id'), n)` (both verified on 18.6). After a bulk load, every identity/sequence must be moved past `max(id)`; the toolkit does this with `./dbmig reset-identity` (dry run, then `--apply`).
- `SCOPE_IDENTITY()`/`@@IDENTITY` → `INSERT ... RETURNING id` or `CURRVAL`/`lastval()`.
- `UNIQUEIDENTIFIER` → `uuid`. `NEWID()` → `gen_random_uuid()` (core function since PG 13; no extension needed). `NEWSEQUENTIALID()` → PG 18 `uuidv7()` (verified on 18.6: time-ordered, `uuid_extract_version` = 7), which keeps B-tree inserts append-mostly like the SQL Server default. Sort order differs: SQL Server orders `uniqueidentifier` by its last byte group, PostgreSQL by bytes left to right, so `ORDER BY` on GUID columns can return a different order.
- PostgreSQL allows explicit inserts into identity/serial columns by default (no `SET IDENTITY_INSERT` needed) — watch for sequence drift.
- `NO CACHE` → `CACHE 1` (the PostgreSQL default). `CREATE SEQUENCE … AS INT` keeps its type; without `AS` the type is `bigint` (verified).
- `sp_sequence_get_range` has no equivalent. Reserve a block by setting `INCREMENT BY` to the block size, or call `nextval` in a loop.
- `IDENTITY()` in `SELECT … INTO` → `CREATE TABLE … AS SELECT row_number() OVER (ORDER BY …) + 99 AS SurrogateKey, …`, then add an identity column if new rows need one.
- `IDENT_CURRENT('t')` → `SELECT last_value FROM <sequence>`; it is not session-scoped in either engine.
