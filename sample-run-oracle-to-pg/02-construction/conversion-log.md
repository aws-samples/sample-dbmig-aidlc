## Datatype decisions
| Oracle | PostgreSQL | Why |
|---|---|---|
| `NUMBER(19,0)` IDENTITY PK (12×) | `bigint GENERATED BY DEFAULT AS IDENTITY` | identity needs an integer type, never `numeric` — non-portable-constructs.md → Sequences/identity |
| `NUMBER(19,0)` FK columns | `bigint` | match the referenced PK type |
| `NUMBER(10,0)` | `bigint` | 10 digits exceed int32 |
| `NUMBER(38,2)` money | `numeric(38,2)` | exact decimal, never float |
| `NUMBER(1,0)` 0/1 flags | `smallint` + `CHECK (col IN (0,1))` | app stores 0/1 and data is copied verbatim; `boolean` would break the copy |
| `DATE` (5×) | `timestamp(0)` | Oracle `DATE` carries time-of-day; `date` would truncate it |
| `TIMESTAMP(6)` | `timestamp(6)` | direct |
| `VARCHAR2(n CHAR)` / `VARCHAR2(64)` | `varchar(n)` | PG counts characters, so ≥ source capacity |
| `BLOB` | `bytea` | `BOOKS_COVER.COVER_IMAGE`; far below the ~1 GB limit |

## Structural decisions
- **System indexes dropped, not recreated:** 16 `SYS_C*` (PK-backing — `PRIMARY KEY` creates its
  own), `SYS_IL0000024567C00002$$` (internal LOB index — PG TOAST manages `bytea`), and the 4
  `DR$BOOKS_TEXT_IDX$*` Oracle Text internals. Recreating them would fail with "already exists"
  or be meaningless. Named CHECK/PK constraints replace Oracle's `SYS_C*` auto-names.
- **IOT → heap + PK:** `PERSISTENT_LOGINS` was the schema's only Index-Organized Table. PG has no
  IOT; the PK's B-tree provides the access path. Physical row clustering is not preserved.
- **FKs + triggers deferred:** written into the same unit files; `dbmig`'s splitter routes them to
  the `--post-data` pass so enforced FKs don't dictate load order and the row trigger can't rewrite
  loaded rows.
- **Parity preserved deliberately:** `ORDERS.customer_id`/`address_id` have **no** FK in the source —
  none was added. `CUSTOMERS.username`/`email` have no unique constraint — none was added.

## Full-text search — the one Manual redesign (approved: PRESERVE)
| Oracle | PostgreSQL |
|---|---|
| `CREATE INDEX BOOKS_TEXT_IDX ON BOOKS(SEARCH_TEXT) INDEXTYPE IS CTXSYS.CONTEXT PARAMETERS ('SYNC (ON COMMIT)')` | `CREATE INDEX books_text_idx ON demo.books USING gin (to_tsvector('english', coalesce(search_text,'')))` |
| `CONTAINS(search_text, :q) > 0` | `to_tsvector('english', coalesce(search_text,'')) @@ to_tsquery('english', :q)` |
| `SYNC (ON COMMIT)` | dropped — GIN is maintained transactionally by PostgreSQL, so there is nothing to sync |
| `TRG_BOOK_SEARCH_TEXT` (row trigger, inline body) | `demo.trg_book_search_text_fn()` PL/pgSQL trigger function + `CREATE TRIGGER` binding; `NVL` → `COALESCE` |

The `search_text` column is retained as `varchar(1000)` so the loaded data stays byte-identical and
the source's plain `IDX_BOOKS_SEARCH` btree is preserved alongside the new GIN index.
Ref: non-portable-constructs.md → Indexes (Oracle Text domain index).

## PL/SQL → PL/pgSQL decisions
- **Packages flattened** to `<package>_<subprogram>` (e.g. `ORDER_PKG.create_order` →
  `demo.order_pkg_create_order`). `convert-code` reported **no** naming collisions. The 5
  `PACKAGE BODY` units are documented no-ops: PG merges spec+body into one routine, so each
  package's complete conversion lives in its single `package__<pkg>.sql`.
- **`PIPELINED` table function redesigned:** `REPORTING_PKG.get_top_books` (`RETURN ... PIPELINED`
  + `PIPE ROW` + companion `RECORD`/`TABLE` types) → a set-returning
  `RETURNS TABLE(...)` function with one `RETURN QUERY`. The Oracle helper types are unnecessary in
  PG. `FETCH FIRST p_limit ROWS ONLY` → `LIMIT p_limit`.
- **`SELECT … INTO STRICT`** used wherever Oracle relied on implicit `NO_DATA_FOUND` (5 routines).
  Plain PL/pgSQL `SELECT INTO` does not raise, which would have silently changed
  `get_condition_name`/`get_genre_name`/`get_customer_full_name` from returning `'Unknown'` to
  returning NULL. Aggregate-only queries kept plain `INTO` (they always return a row).
- **`COMMIT` removed** from 4 procedures (`archive_old_orders`, `clear_shopping_cart`,
  `process_customer_offer`, `set_book_featured`) — the caller owns the transaction, and the
  equivalence harness must be able to roll each test back.
- **`DELETE FROM (subquery)`** in `archive_old_orders` → a direct `DELETE FROM demo.orders WHERE …`.
- **`SYSDATE - p_days_old`** → `now() - make_interval(days => p_days_old::int)` (PG needs an interval).
- **Expression mapping:** `NVL`→`COALESCE`, `SYSDATE`/`SYSTIMESTAMP`→`now()`,
  `DBMS_OUTPUT.PUT_LINE`→`RAISE NOTICE`, `SQL%ROWCOUNT`→`GET DIAGNOSTICS … ROW_COUNT`,
  `RAISE_APPLICATION_ERROR`→`RAISE EXCEPTION … USING ERRCODE`, `REGEXP_LIKE(x,p)`→`x ~ p`,
  `TRUNC(created_on)`→`created_on::date`, `DETERMINISTIC`→`IMMUTABLE`,
  `PARALLEL_ENABLE`→`PARALLEL SAFE`. Read-only routines marked `STABLE`.

## Two semantic traps caught during conversion (both would have silently changed results)
1. **`REGEXP_REPLACE` needs `'g'`.** Oracle replaces **all** matches; PostgreSQL replaces only the
   **first** without the flag. `VALIDATION_PKG.is_valid_isbn` strips non-ISBN characters, so without
   `'g'` it would have mis-validated every ISBN. Fixed: `regexp_replace(p_isbn,'[^0-9X]','','g')`.
2. **NULL string concatenation.** Oracle treats NULL as `''` in `||`; PostgreSQL propagates NULL.
   `GET_CUSTOMER_FULL_NAME` (`first_name || ' ' || last_name`) would return NULL instead of a
   partial name whenever either part was NULL. Fixed with `coalesce(...,'')` on each operand.

## Deliberately deferred to later phases
- Deferred FKs + the `CREATE TRIGGER` binding → `apply-schema --post-data` after the data load.
- **Identity advance to `MAX(id)`** on the 12 IDENTITY tables after the load, or the next
  application insert collides.
