## Defects found and fixed during the migration
1. **`REGEXP_REPLACE` missing `'g'` flag** — Oracle replaces all matches, PostgreSQL only the
   first. Would have broken `validation_pkg_is_valid_isbn`. Proven real by negative control
   (Oracle 13 vs PG-without-`g` 15).
2. **NULL string concatenation** — Oracle treats NULL as `''` in `||`. Fixed with `coalesce` in
   `get_customer_full_name`.
3. **SQLSTATE collision (found in Validation)** — `ORA-20002` had been mapped to `P0002`, which is
   PostgreSQL's built-in `no_data_found`. Remapped to the unassigned `U0` class
   (`U0001`/`U0002`), re-applied and re-verified as three distinct codes.

## NOT done — requires explicit, step-by-step direction
**The production cutover has NOT been executed.** Plan approval is not execution. Schema, code and
data are live and validated in `demodb.demo`, but no application traffic has been switched.
Cutover is a high-risk production action and will only be run interactively, step by step.

**Precondition (runbook step 0.1):** the application build carrying the four carry-forward changes
must be ready and tested first — the app will not work correctly without them:
1. `CONTAINS(...)` → `to_tsvector('english', coalesce(search_text,'')) @@ to_tsquery('english', :q)`
2. catch SQLSTATE `U0001`/`U0002` instead of `ORA-20001`/`ORA-20002`
3. the 4 converted procedures no longer `COMMIT` — the caller must commit
4. package calls become `demo.order_pkg_create_order(...)` etc.
