## Blocked items
**None.** Every construct has a supported path.

## Top risks / items needing explicit validation
1. **Oracle Text → PG full-text (item 16)** — the one genuine redesign. No `CONTAINS()` calls exist in
   the app layer here (search is trigger-maintained), so risk is contained to the index + trigger.
2. **Empty-string vs NULL** — Oracle `''` = NULL; PG `''` ≠ NULL. Assert in equivalence tests.
3. **`DATE` → `timestamp(0)`** — verify no time-of-day truncation.
4. **Identity advance after full load** — explicit key values are copied; identity must be reset to
   `MAX(id)` or the next insert collides.
5. **Procedure `COMMIT` removal** — required for net-effect testability; verify behavior unchanged.
6. **Numeric rounding / implicit coercion** — `NUMBER` vs `numeric`; assert numeric aggregates within tolerance.

Known semantic differences to test are enumerated in `engines/oracle-to-postgresql/checks/equivalence-spec.md §6`.
