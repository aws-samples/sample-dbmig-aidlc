# Non-portable Oracle → MySQL constructs (field-tested checklist)

Patterns with no direct Aurora MySQL equivalent and how to convert them, distilled from a real
Oracle `DEMO` schema → Aurora MySQL 8.0 run (14 tables, 12 identity sequences, 5 packages, 5
procedures, 5 functions, 1 trigger). Flag, don't silently approximate.

## 1. Packages
MySQL has no packages. Flatten each public subprogram to a standalone routine
`demo.<package>_<subprogram>`. **One routine per file/unit** — the apply path executes a unit
in a single `cur.execute`; a compound `BEGIN..END` routine is fine as one statement, but
multiple routines in one file are not. Package spec → no DDL (signatures only); convert the
body's subprograms. Sibling calls become calls to the flattened routine.

## 2. Sequences / identity
`GENERATED BY DEFAULT AS IDENTITY` → `bigint AUTO_INCREMENT` (set `AUTO_INCREMENT=<start>`).
The Oracle `ISEQ$$_*` sequences that back identity columns are internal — do not migrate them
separately. `migrate-data` reseeds AUTO_INCREMENT (MAX+1) after load. Standalone Oracle
SEQUENCEs used by app code have no per-table MySQL analog and need redesign (one AUTO_INCREMENT
table, or a sequence-emulation table).

## 3. Stored routine parameters: no DEFAULTs
MySQL procedure/function parameters cannot have default values. Drop Oracle
`p_x DEFAULT v` defaults (the caller must pass the value) and document it.

## 4. PL/SQL → MySQL SQL/PSM idioms
- `RAISE_APPLICATION_ERROR(-n,'msg')` → `SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT='msg'`.
- `EXCEPTION WHEN NO_DATA_FOUND` → `DECLARE CONTINUE HANDLER FOR NOT FOUND SET ...`.
- `SYSDATE`/`SYSTIMESTAMP` → `NOW(6)`; `SYSDATE - n` → `DATE_SUB(NOW(6), INTERVAL n DAY)`;
  `TRUNC(d)` → `DATE(d)`; `NVL` → `COALESCE`/`IFNULL`; `||` → `CONCAT` (wrap with IFNULL to keep
  Oracle's NULL-as-empty concat); `RETURNING id INTO` → `LAST_INSERT_ID()`.
- `REGEXP_LIKE(x,p)` → `x REGEXP p` (escape backslashes for the MySQL string literal);
  `REGEXP_REPLACE` exists in MySQL 8.
- PIPELINED table function → a PROCEDURE returning a result set (plain `SELECT`);
  `FETCH FIRST n ROWS ONLY` → `LIMIT n` (LIMIT accepts a routine parameter).

## 5. Data-modifying functions
A stored FUNCTION that runs INSERT/UPDATE/DELETE triggers `ERROR 1418` at CREATE when binary
logging is enabled (needs `log_bin_trust_function_creators=ON`). Aurora MySQL typically has
`log_bin` OFF, so it is allowed; otherwise prefer a PROCEDURE or set the parameter.

## 6. Triggers
- Create the trigger in the table's schema: qualify the name
  (`CREATE TRIGGER demo.t ... ON demo.tbl`) or you get `ERROR 1435 'Trigger in wrong schema'`
  when the connection's default database differs.
- `BEFORE INSERT OR UPDATE` (Oracle, multi-event) → **two** triggers (one per event).
- Keep each trigger a **single statement** (e.g. `SET NEW.col = ...`) so the `;`-based statement
  splitter does not break a `BEGIN..END` body; multi-statement bodies need careful handling.

## 7. DDL is auto-committed (idempotency)
MySQL auto-commits each DDL statement (no transactional rollback). If a multi-statement unit
fails part-way, earlier statements are already committed — a naive re-run then hits
`duplicate key/constraint` errors. Drop the partially-applied objects before retrying.

## 8. Index length / full-text
utf8mb4 caps an InnoDB index key at 3072 bytes, so a `varchar(>768)` column cannot be fully
indexed → use a **prefix index** (`col(255)`). An Oracle Text (`CTXSYS.CONTEXT`) index →
a MySQL `FULLTEXT` index.

## 9. Types
`DATE` → `datetime` (Oracle DATE carries time); `TIMESTAMP(6)` → `datetime(6)`; `NUMBER(1,0)`
flag → `tinyint` + `CHECK (col IN (0,1))`; `NUMBER(19,0)` Long ids → `bigint`; `NUMBER(38,2)` →
`decimal(38,2)`; `VARCHAR2(n CHAR)` → `varchar(n)` (utf8mb4); `BLOB` → `longblob`;
`ROWID`/`UROWID` → no equivalent (redesign). Empty string `''` is NULL in Oracle but NOT NULL in
MySQL — validate NOT NULL columns and comparisons.

## 10. Schema = database; identifier case
An Oracle schema maps to a MySQL **database** (here `DEMO` → database `demo`, lower-cased).
Qualify objects `demo.<obj>`. On Linux, table-name case sensitivity depends on
`lower_case_table_names` — be consistent (lower-case).
