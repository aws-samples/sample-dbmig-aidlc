# Conversion log — dbo → dbo (PostgreSQL 17)

Prompt volume: 4 schema + 4 code + 5 test bundles + 3 shared context files ≈ 30K tokens.

## Datatypes
`int IDENTITY` → `integer GENERATED BY DEFAULT AS IDENTITY`; `nvarchar(max)` → `text` (searched columns
`citext`); `nvarchar(n)` → `varchar(n)`; `nchar(n)` → `char(n)`; `bit` → `boolean`; `datetime2` →
`timestamp(6)`; `datetime` → `timestamp(3)`; `money` → `numeric(19,4)`; `uniqueidentifier` → `uuid`
(`newid()` → `gen_random_uuid()`); `xml` → `xml`; `getdate()` defaults → `localtimestamp`.
`"order"` is reserved → quoted table; `"schema"`/`"object"` columns quoted.

## Results
- Tables 20/20 first pass (FK guard: FK counts equal source). Code 25/25 first pass. Post-data 6/6.
- Equivalence tests found **3 conversion defects**, fixed and re-verified (auto-resolved in follow-up):
  1. `ufnget*statustext(p_status smallint)` — callers pass integers; PostgreSQL will not narrow
     `integer → smallint` during function lookup → parameter now `integer` (engine check §16).
  2. `ufnleadingzeros(123456789)` — SQL Server returns `'0000000*'` (overflow marker), not `'*'`.
  3. test harness: `INOUT` param needs a variable when `CALL`ed from PL/pgSQL.
- `citext` extension must be in the app's `search_path` schema (`dbo`), otherwise `LIKE` silently stays
  case-sensitive (engine check §17 — found at app validation).

## Routine contract changes (application must follow)
Result-set procedures are now functions: `SELECT * FROM dbo.uspgetbillofmaterials(id, date)`,
`uspgetwhereusedproductid`, `uspgetauthormanagers`, `uspgetmanagerauthors`, `uspgettopregion`,
`uspshoppinglevelamount`, `uspgetproductdata()` (was a cursor OUTPUT). `usplogerror`/`uspprinterror`
take the error fields as parameters.
