## Changes in this run
1. **`AK_BillOfMaterials_ProductAssemblyID_ComponentID_StartDate` → `UNIQUE … NULLS NOT DISTINCT`.** `productassemblyid`
   is nullable; SQL Server's unique index admits one NULL per key, PostgreSQL's admits many. Found from the new baseline
   ("UNIQUE index allowing one NULL", verified on both engines) — `skills/sqlserver-to-postgresql-playbook/references/target-baseline-aurora-postgresql-18.md`,
   `skills/sqlserver-to-postgresql-playbook/references/ansi-sql/constraints.md`.
2. **`citext` type written as `dbo.citext`** (book, offer, referencedata). First apply failed 3/20 with
   `type "citext" does not exist`: `CREATE EXTENSION citext SCHEMA dbo` puts the type in `dbo`, which is not on the
   apply session's `search_path`. The previous run passed only because its target already had `citext` installed.
   Engine check §17 (`skills/sqlserver-to-postgresql-playbook/references/tsql/collations.md`).
